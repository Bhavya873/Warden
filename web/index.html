What Warden Does: Warden is a warehouse robotics project that stops robots from moving into the same cell. Normally a robot asks a central server before every move; Warden lets robots answer most of those checks locally, so the server only gets contacted when a conflict is actually possible.

How It Works: Each robot keeps a small local Ribbon filter that instantly confirms a cell is free, or flags it as possibly occupied. Only the uncertain cases go to the server, which checks its ring buffer, the authoritative record of currently claimed cells — and makes the final call.

How to Use It: Run the simulation to compare Warden against a baseline where every check hits the server. The live WebSocket dashboard runs both side by side, showing robot activity, server requests, and response times, so you can see how often Warden skips the server call and what that does to performance.

Benefits: With most cells empty most of the time, Warden cuts network traffic and speeds up the common case, where robots keep moving without waiting on the server. Safety doesn't depend on the filter: the server still resolves every uncertain case before a robot moves into a cell that might be occupied.

Tradeoffs: A false positive, when the filter flags a free cell as maybe-occupied, costs an extra server request, shrinking the benefit. Warden also assumes occupancy doesn't change too fast: the busier the warehouse, the more filter refreshes and server checks it needs.

How It Was Built: The Ribbon filter and ring buffer are written in Rust for speed; the simulation is Python, so robot behavior and warehouse conditions stay easy to iterate on. PyO3 bridges the two, and a WebSocket dashboard shows Warden and the baseline running side by side in real time.
